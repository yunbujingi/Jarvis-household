# 0.3.0依赖安全复核

2026-11-15，pip-audit2.10.1对原锁定依赖返回cryptography46.0.7共7条告警；按ID/别名去重为4组。不是7个独立漏洞。没有添加忽略项。

| 告警 | 适用性判断与处理 |
| --- | --- |
| PYSEC-2026-3554 / CVE-2026-69248 | X.509名称约束验证问题；本项目直接使用AES-GCM，WSS使用Python ssl，不调用cryptography该验证器；仍升级修复依赖 |
| PYSEC-2026-3552 / CVE-2026-69247 | PKCS7解密错误/时序差异；本项目未调用PKCS7接口，仍升级 |
| PYSEC-2026-3553 | 异常证书链验证资源消耗；本项目未调用该证书验证器，仍升级 |
| GHSA-537c-gmf6-5ccf | wheel携带的OpenSSL已知问题；运行包确有相关原生组件，未以“只用AES”排除供应链影响，升级wheel |

修复采用cryptography50.0.2；上游说明包含相关安全修复及OpenSSL更新，见[官方变更记录](https://cryptography.io/en/latest/changelog/)。本项目没有修改加密格式，旧版密文夹具和备份/恢复回归验证解密兼容。50系列不再提供Intel Mac wheel，因此没有声明支持该平台。

新锁定依赖重新扫描未发现已知漏洞；最终CI仍会独立扫描。初次本机扫描因缓存目录权限失败，明确作为工具故障，改为本任务独占缓存目录后重跑；没有把失败当作通过。

扫描范围为锁定的Python直接、间接、开发与构建工具；基础系统镜像、Python解释器和未来外部服务不因此被认证安全。漏洞数据库会变化，维护者需持续更新锁与重新验收。CI服务不可达会失败，须区分外部服务故障与漏洞告警，不得全局忽略。
